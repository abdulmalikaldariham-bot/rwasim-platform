# ربط قاعدة البيانات والنشر على الإنترنت

المسار الموصى به: **Supabase** لقاعدة البيانات والمصادقة والملفات، و**Vercel** لاستضافة الموقع (مع GitHub للنشر التلقائي).

## 1) إنشاء مشروع Supabase

1. من https://supabase.com أنشئ مشروعًا جديدًا. اختر المنطقة الأقرب (مثلًا Frankfurt أو Mumbai) واحفظ كلمة مرور قاعدة البيانات.
2. من **Project Settings → API** انسخ:
   - `Project URL`
   - `anon public key`
   - `service_role key` (سري — لا يوضع في المتصفح ولا في GitHub)

## 2) تطبيق قاعدة البيانات

**بالطريقة الأسهل (Supabase CLI):**

```bash
npx supabase login
npx supabase link --project-ref <PROJECT_REF>
npx supabase db push
```

**أو يدويًا:** افتح **SQL Editor** ونفّذ ملفات `supabase/migrations` بالترتيب:

1. `20261015000100_schema.sql`
2. `20261015000200_functions.sql`
3. `20261015000300_rls.sql`
4. `20261015000400_storage_and_seed.sql`

الملف الأخير ينشئ حاويات التخزين الخاصة (الشواهد، التقارير، ملفات الاستيراد) والإدارات الخمس، وسنة 2026 الانتقالية بأوزان 20٪ لكل إدارة.

## 3) إعدادات المصادقة (مهم أمنيًا)

من **Authentication → Providers → Email**:

- أوقف **Allow new users to sign up** (التسجيل الذاتي مغلق؛ الحسابات ينشئها المدير التنفيذي أو مسؤول النظام).
- حتى لو فُتح التسجيل بالخطأ، فأي حساب لم يُسند له دور من الخادم يُنشأ **معطلًا** ولا يرى أي بيانات (مختبر).

من **Authentication → URL Configuration**: ضع `Site URL` = رابط الموقع بعد النشر.

راجع [الدليل 03](03-حساب-المدير-التنفيذي-الأول.md).

## 5) النشر على Vercel

1. ارفع المشروع إلى مستودع GitHub **خاص**.
2. من https://vercel.com: **Add New → Project** واختر المستودع (يتعرف على Next.js تلقائيًا).
3. أضف متغيرات البيئة:

| المتغير | القيمة |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Project URL |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | anon key |
| `SUPABASE_SERVICE_ROLE_KEY` | service_role key |
| `NEXT_PUBLIC_SITE_URL` | رابط الموقع النهائي |

4. **Deploy**. كل دفع لاحق إلى الفرع الرئيسي ينشر تلقائيًا.

### توليد PDF على Vercel

يستخدم المسار `/api/reports/[id]/pdf` الحزمة `@sparticuz/chromium` تلقائيًا (لا تضع `CHROMIUM_PATH` على Vercel). يحتاج المسار إلى ذاكرة 1024MB على الأقل؛ إن ظهر خطأ نفاد الذاكرة ارفعها من **Settings → Functions**. وفي كل الأحوال يبقى زر **طباعة** في صفحة التقرير بديلًا يحفظ PDF من المتصفح بالتنسيق نفسه.

عند اعتماد التقرير تُحفظ نسخة PDF منه في التخزين (`reports/{id}/approved.pdf`) وتُقدَّم هي في التنزيلات اللاحقة.

## 6) النسخ الاحتياطي والاستعادة

- **تلقائي:** Supabase يحتفظ بنسخ يومية (7 أيام في Pro). يُنصح بخطة Pro لبيانات مؤسسية، مع تفعيل Point-in-Time Recovery إن أمكن.
- **يدوي:** من **Project Settings → Database → Connection string (Session pooler)** انسخ الرابط، ثم:

```bash
SUPABASE_DB_URL="postgresql://..." npm run backup        # ينتج backups/rawasim-YYYYMMDD-HHMMSS.dump
SUPABASE_DB_URL="postgresql://..." npm run restore -- backups/rawasim-....dump
```

يتطلب `pg_dump`/`pg_restore` (حزمة PostgreSQL client). جرّب الاستعادة على مشروع اختبار أولًا.

## 7) بعد النشر

1. سجّل الدخول بحساب المدير التنفيذي.
2. **الإعدادات ← المستخدمون:** أضف مديري الإدارات الخمس والموظفين وأعضاء المجلس (تظهر كلمة مرور مؤقتة مرة واحدة).
3. **الإعدادات:** راجع حدود أسابيع الربع الرابع 2026 واعتمدها.
4. **الخطط التشغيلية ← استيراد من Excel:** ارفع ملف الربع الرابع، وراجع، واحفظ كمسودات، ثم اضبط الأوزان واعتمد.
5. أنشئ خطة إدارة تمكين يدويًا أو من القالب.
